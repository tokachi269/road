# Agent作業手順

この文書は、agentが変更を実装するときの確認順を示します。
製品仕様のownerではありません。

## 変更前

1. 変更する判断のownerを特定する。
2. 同じ判断を持つUI、JSON、consumerを探す。
3. 既存testで再現できるか確認する。
4. 変更後に必要な手動確認を決める。

局所的な不具合へ、新しいframeworkや永続データを追加しません。
既存のownerで表現できない場合だけ、構成変更を検討します。

## 実装中

consumer側で同じ判断を再実装しません。
推測によるfallbackで不正な入力を隠しません。

想定より変更範囲が広がった場合は作業を止めます。
第二のowner、永続mirror、層をまたぐ依存が必要になった理由を確認します。

## 検証

変更したfault classに対応するtestを実行します。
コマンドは[検証方法](../testing.md)を参照してください。

token scanはbehaviorを証明しません。
render画像は寸法やtopologyを証明しません。
build成功はゲーム内表示を証明しません。

## 完了報告

次の内容を分けて報告します。

- 変更した内容
- 自動検証の結果
- 手動で確認した内容
- 未確認の内容
- commitとpushの有無

未確認事項を推測で埋めません。
commit、push、ゲーム環境への配置は明示依頼がある場合だけ行います。
